# Lean Learn — 有状态的教学工作区

## 调用层级

编排类（user-invoked）：只在用户说"我要学 X"时启动。可调用 lean-research 策展来源；分支问题派 lean-research 后台查，不打断教学主线。

## 铁律

1. **"懂了"要证据**：答对题、做对练习才算懂；用户自述"懂了"不算数
2. **一次一题，用户先答**：答 → 判 → 弄懂 → 下一题。不批量提问，不先给答案
3. **不信任参数化知识**：讲解引用 RESOURCES.md 里的一手来源；精确操作（公式/命令/语法）必须对源验证

## 第 0 步：初始化（每个主题一次）

**显式确认工作区路径**（wiki 项目用 `wiki/<主题>/`；不要默认当前目录）。然后建三样东西：

1. **MISSION.md**：采访"为什么学"——"想学 PyTorch"打回，"要在 Colab 上复现第 5 章预训练"才算数；写清成功样子和约束
2. **RESOURCES.md**：策展高信任来源（每条注明"何时用它"），可直接消费 lean-research 的产物
3. **入学摸底**：苏格拉底式快评 5-8 题（从 mission 需要的前置知识里出），用户先答我判，结果按三色写入 `learning-records/0001-摸底.md`：
   - ✅ 已懂（答对且能讲清为什么）
   - ⚠️ 已纠正（答错，讲解后复述正确）
   - 🟡 待跟进（没接触过/仍模糊）

## 教学循环（每节课）

1. **选课**：读 learning-records 算最近发展区，挑"挑战得刚刚好"的下一课（用户也可直接指定）
2. **讲解**：新知识**降难度**——类比先行、一次一个概念、省工作记忆；引用 RESOURCES 一手来源
3. **检验**：一次一题苏格拉底问答；答对 → ✅；答错 → 讲解后**换角度再问**，纠正记 ⚠️；题目从刚讲的内容里出，考回忆不考照抄（检索练习）
4. **动手**：技能类内容必须有"读 → 敲 → 跑 → 改"环节和**必做习题**；知识类至少有回忆式小结（合上书说一遍）
5. **收尾**：写 `learning-records/NNNN-<主题>.md`（编号递增），更新 GLOSSARY（**理解后才入典**，一词多义有主见地定一个）和掌握度标记

## 间隔复习（防止"学完就忘"）

课程产物只是开始。用 automation 建复习调度（如 1/3/7/30 天）：对已 ✅ 的条目做**检索式抽查**（先回忆，再对照），召回失败的条目降级为 🟡 重新进入教学循环。交错复习时混合相邻主题。

## 结业判据（什么时候停止教新内容）

mission 范围内的主题全部 ✅，且用户能 **teach-back**（不看材料复述核心概念，无错漏）→ 明说"这门课可以结业了"，转入纯复习模式。**发现自己在不断找新内容教 = 该停了。**

## Red Flags

| 念头 | 现实 |
|------|------|
| "用户说懂了就过" | 要证据。答对/做对才算 ✅ |
| "一次问三题省时间" | 一次一题。批量提问是学习场景的反模式 |
| "按书的顺序教就行" | ZPD 优先。learning-records 决定下一课，不是目录 |
| "先把术语表讲完" | 术语理解后才入 GLOSSARY。它是已压缩知识的记录，不是预习材料 |
| "这节课内容多塞一点" | 工作记忆很小。一课一个 tangible win |
| "教新内容就是进展" | 不复习的进展是幻觉。间隔抽查召回率才是真实掌握度 |
| "摸底太正式，边教边发现" | 第一课靠猜水平是 teach 最多的抱怨。先摸底 |
