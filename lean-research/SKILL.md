# Lean Research — 证据优先调研

**铁律：每个论断都回溯到拥有它的源头。二手转述不是证据，只是线索。**

## 第 0 步：锁定问题（轻量，不做全套拷问）

把需求变成一个**可回答、有边界**的调研问题。只在两种情况下问用户（最多一轮）：问题有多种合理解读；边界决定结论（时间范围、市场、口径）。其余自己定并写入"搜索边界"附录。

## 第 1 步：后台调研（派 subagent，用户继续干活）

派后台 agent 执行阅读，主会话只做综合。调研 agent 的任务契约：

1. **一手来源优先**：官方文档、源码、监管文件、财报原文、API 文档、原始论文。二手文章只用来发现一手来源，不作为引用
2. **多种措辞搜索**，不只第一个显而易见的关键词；覆盖到"再搜也不改变结论"为止
3. 记录**搜索边界**：查了哪些源、时间范围、排除了什么、为什么
4. 原始笔记写入临时文件（含每条来源的 URL 和关键摘录），**不要把全文粘回主会话**

## 第 2 步：证据分级与引用循环检测（主会话）

对每条关键论断标注分级：

| 分级 | 含义 | 权重 |
|------|------|------|
| **[一手]** | 源头本身（文档/财报/法规/代码） | 可引用 |
| **[二手]** | 有编辑把关的转述（权威媒体/官方博客） | 可用，需注明 |
| **[观点]** | 个人博客/社媒/评论 | 只作情绪参考，不作事实依据 |

**引用循环检测**：N 个来源说同一件事，先查是否追溯到同一源头——是，则仍只算**一条**证据，并在文中明说。

## 第 3 步：综合成文

单文件交付（Markdown 笔记；用户要报告则 HTML）。结构固定：

1. **结论前置**（3-5 条，每条带证据分级角标）
2. **证据表**：论断 | 分级 | 来源（逐条挂链接）
3. **矛盾与不确定性**：冲突证据并列呈现，不掩盖；证据薄就明说"薄"
4. **可证伪条件**：每条核心结论标注"什么证据出现会推翻它"
5. **附录：搜索边界**（查了什么、时间范围、排除项）——让覆盖范围可审计

**报告模式**（equity/FX/行业覆盖类）：在用户偏好时启用——表格 + 嵌入图表 + 乐观/中性/悲观情景 + 显式假设。

## 存放

按目标项目既有约定。wiki 项目：源件入 `raw/`（只读），笔记入 `wiki/<分类>/`，更新 index.md 和 log.md。无约定时说明存放位置。

## Red Flags

| 念头 | 现实 |
|------|------|
| "官网太长，看个二手总结就行" | 二手只用来找一手。引用必须落在源头 |
| "三个来源都这么说" | 先查引用循环。同一源头的三次转述 = 一条证据 |
| "结论加'可能/或许'就不用验证了" | 模糊措辞不是免责。标注证据分级 |
| "网上搜不到就按经验写" | 参数化知识不可信。查不到就明说"未找到一手来源" |
| "把所有材料读完再动笔" | 覆盖到边际收益递减即停，边界写进附录 |
| "矛盾证据挑有利的说" | 并列呈现。掩盖矛盾的调研是宣传 |
