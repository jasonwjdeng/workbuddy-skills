# AK 四级输出阶梯 — 同一内容的四种介质

## 用途

把任意主题按 Karpathy 的阶梯升级介质：**写作 → 图表 → 网页 → 视频**。
每一级都比上一级更好理解，也更贵、更难校对。目标不是"做到最高级"，而是**选对那一级**。

四个可直接使用的提示词模板见 `references/prompts.md`。本文件是执行流程与验收标准。

## 第 0 步：定级（不要跳过）

按用户的**理解障碍**选，不按主题类型选：

| 障碍 | 级别 | 判据 |
| --- | --- | --- |
| 说法含糊，抓不住准确意思 | 一级 · 写作 | 需要一句话只有一个意思 |
| 它是分支的，用文字讲就塌成一串 | 二级 · 图表 | 信息本身是并行结构 |
| 我不信，想自己拖一下看看 | 三级 · 网页 | 概念里有可调参数 |
| 看过文字也看过图，还是没感觉 | 四级 · 视频 | 需要直觉和节奏 |

- 用户没指定级别 → 默认**一级**（最便宜，且后面三级都要先想清内容才能做）。
- 用户说"只做一个" → 做**二级**（约束最强，会反过来逼你把概念想清楚）。
- 拿不准 → 直接问，别猜。级数越高返工越贵。

## 一级 · 受控语言写作（ASD-STE100）

### 核心动作

1. **优先用英文版模板**（`references/prompts.md` 第 1B 节）。
2. **英文提示词 ≠ 英文输出**，两者独立：ASD-STE100 的受控词汇表是英文的（约 900 个批准词 + 技术名词），中文没有官方受控表。想要完整的受控词汇约束，`OUTPUT LANGUAGE` 必须填 `English`；填中文只用得到**句法纪律**（短句、主动、一词一义）。这一点每次都要跟用户讲清。
3. 八条硬规则照抄模板，不要自己精简：
   - 一句一意（操作句 ≤20 词、描述句 ≤25 词）
   - 只用主动语态（被动仅在无法避免时用，且必须写出施动者）
   - 只用一般现在时（不用进行时、不用完成时）
   - 一词一义，全程不换同义词
   - 名词堆叠 ≤3
   - 三个以上并列项改竖排列表
   - 术语第一次出现就地定义
   - 一段一主题，≤6 句
4. **禁止隐喻——这是最费劲也最出彩的一条。** 遇到隐喻式术语（注意力、门控、记忆、遗忘、幻觉、循环），不要翻译这个词，把它**替换成机制**：
   - attention → 做 query / key / value → 比较 → 打分 → 加权值向量 → 求和（5 条可执行句）
   - 通用招式：**把名词换成步骤**。
5. 结构顺序固定：是什么 → 怎么工作 → 能做什么 → 不能做什么。
6. 要求「做到八成合规」，并让模型在末尾附**自检表**：逐条对照八条标出是否做到，再说明哪 20% 是刻意放松的、代价是什么。

### 交付

中文需求 → 给**中英双版** + 合规自检表；只有中文版时才需声明"中文只继承句法纪律、没有受控词汇"。

## 二级 · 图表

### 核心动作

1. **先出规划，再出图。** 先给一句话的图结构规划（画几张、每张回答什么问题），等用户确认。这一步能省掉整轮返工。
2. 每张图只回答一个问题；图与图之间**递进**——先讲"长什么样"，再讲"怎么动起来"。
3. 结构只用五类：流程、层级、对比、流向、矩阵。不要装饰性图形。
4. **至少一张图标出「数据形态」**——每一步的输入输出是什么形式、什么量级。
   例：`字符串 → 词元列表 → 3×768 个数字 → 100 层 → 下一个词元`。这是纯文字讲不清、图真正赢过文字的位置。
5. **图中任何数值必须标「示意值」还是「实测值」。** 这是四级里最容易骗人的地方——示意值画得像实测值，读者会当成真模型参数。
6. 每图配 1–2 句图注，指出最值得看的位置。

### 实现与落盘

1. 先在对话内用 `show_widget` 出内联 SVG 确认版式。
2. 落盘时：`var(--font-sans)` 换成具体字体栈
   （`'PingFang SC','Hiragino Sans GB','Microsoft YaHei',system-ui,sans-serif`，写在根 `<svg style>` 上让子元素继承），并补一层背景 `rect` 保证深色主题下可读。
3. 多面板竖向拼接：把 SVG body 写成临时文件，用 Python 正则 `\b(y|y1|y2|cy)="N"` 整体平移纵坐标。
   **坑**：绝对路径数据（如 `M440 88 L434 88 ...`）不会被属性正则平移，必须单独改写坐标。
4. 落盘位置：`<知识库>/<主题目录>/_attachments/<名>.svg`，笔记里用 `![[名.svg]]` 引用。
5. **渲染校验**：本机 `qlmanage` 在该沙箱下不出图，改用无头 Chrome ——
   `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu --no-sandbox --force-device-scale-factor=1.6 --window-size=W,H --screenshot=/tmp/out.png "file:///<url-encoded-abs-path>"`，再用 Read 看图逐项核对坐标与文字。SVG 的排版错误肉眼看源码发现不了。

## 三级 · 可交互网页

### 核心动作

1. **单文件 + 零外部依赖**：不引用任何 CDN、外链字体、外链图片，离线双击可开。交付前统计 `http://` / `https://` 出现次数，应为 0。
2. **交互背后必须是真计算**，不是预设动画——公式要在页面上真的跑（例：`softmax(Q·Kᵀ/√d/T)` 与 `Σwᵢ·Vᵢ`）。
3. 分 2–4 个区块，按「是什么 → 怎么变 → 为什么这样设计」递进。
4. 至少一块可交互：调输入（滑杆/点选）→ 实时重算 → 结果立刻变化。
5. 默认状态就要有信息量，不能是一屏空白等操作。
6. 文案里引用到的数字**一律运行时计算回填**，不许写死——否则改了数据忘了改文案，图和话会互相打脸。
7. 页脚标注：本页数据是示例值还是真实值、真实值来自哪里。
8. 交付时把默认状态下的关键数值单独列给用户核对。

### 校验（不要只看静态截图）

1. 复制一份 HTML，在 `</body>` 前注入 `window.addEventListener('load', ...)`：`.click()` 按钮、给 `input[type=range]` 赋值后 `dispatchEvent(new Event('input'))`，并把关键计算结果 dump 到一个 `position:fixed` 的调试块里再截图——一次同时校验「界面正确」+「数值正确」。
2. 先注入 `window.onerror` 把错误画到页面上，截图就能看到 JS 是否报错。
3. 长页面无法滚动截图时，用 `display:none` 隐藏前面几个 `<section>`，让目标区块顶到页面顶部。
4. **踩过的坑**：`<span>` 当容器必须显式设 `display:block`，否则 `width` 不生效（条形图会全是空的）。

## 四级 · 讲解视频

3b1b 风格 = 深色底 + 平滑缓动 + 逐层揭示 + 旁白与画面同步（不是 Manim 那种手绘数学动画）。

### 执行顺序（顺序错了会白干）

1. **先写旁白稿**，按场景分段，每段 1–2 句；场景数 8–10，从"提出一个问题"开始，到"一句总结"结束。
2. **先合成旁白、量出每段真实时长**，再据此排画面起止时间。时间轴是**算出来的**，不是先画后配出来的。
3. 画面：单个 Canvas + 纯函数 `renderFrame(t)`，**必须确定性**——不依赖 CSS 动画或真实时钟，任意时刻都能复现同一帧。场景交叉淡入淡出用一个 `sceneAlpha(t, scene)` 处理。
4. 至少一处「数值/权重/概率」可视化，画面数字要和旁白说的对得上。

### 本机链路（无 ffmpeg，实测可用）

本机**没有 ffmpeg/ffprobe，也没有 brew**，但有 `swift`/`swiftc`、`avconvert`、`afconvert`、`afinfo`、`say`、Google Chrome。

1. **旁白**：`say -v Ting-Ting -o s.aiff "文本"` → `afinfo` 取 `estimated duration` → `afconvert -f WAVE -d LEI16@22050 -c 1 s.aiff s.wav`。
   用 Python `wave` + `array('h')` 按时间点把各段拼进一条定长静音轨，**总长必须等于视频总长**（多退少补，末尾留白）。中文务必指定中文发音人。
2. **抓帧**：Chrome 无头 + CDP（`pip install websockets`）。
   - `--headless=new --remote-debugging-port=N --user-data-dir=<临时目录>`，从 `http://127.0.0.1:N/json/list` 取 `webSocketDebuggerUrl`。
   - `Emulation.setDeviceMetricsOverride` 锁死视口；每帧 `Runtime.evaluate` 调 `renderFrame(t)`，再 `Page.captureScreenshot`。
   - **性能关键：JPEG q95 比 PNG 快约 5 倍**（1280×720 下 52ms vs 262ms/帧）。1756 帧 PNG 要 8 分钟，JPEG 只要 2 分钟。
   - 每帧启动一次 `--screenshot` 是行不通的（一次进程启动/帧）；大图拼 sprite sheet 也不行（超过 canvas 边长上限）。
3. **编码**：`swiftc -O -swift-version 5` 编译一个 Swift 程序（**必须加 `-swift-version 5`** 规避 Swift 6 严格并发报错）：
   - `AVAssetWriter` + `AVAssetWriterInputPixelBufferAdaptor` 把图片序列写成无声 MP4（pixel format 用 `kCVPixelFormatType_32BGRA`，CGContext 的 bitmapInfo 配 `premultipliedFirst | byteOrder32Little`）。
   - 再用 `AVMutableComposition` 把无声 MP4 与 WAV 合轨，`AVAssetExportSession` 导出成片。
   - `finishWriting` / `exportAsynchronously` 是异步回调，脚本里用 `DispatchSemaphore` 等。

### 验证与交付

1. **从成片抽帧核对**，不要只看渲染源帧：写个 Swift 小程序用 `AVAssetImageGenerator` 抽帧，并打印 duration / 轨道尺寸 / fps / isPlayable。
2. 交付前**必须**说明三项折扣：
   - 配音是 **机器音还是拟真音**（本地 `say` 是机器音；要质感需 ElevenLabs 之类，无 key 就用本地并说明）
   - 哪些数据是**示意值**
   - 音画同步**有没有人工听过**（时序是算出来的，但"听一遍确认"常常被跳过）
3. **环境噪音**：Chrome 会尝试写 `~/Library/Application Support/Google/GoogleUpdater/*` 被沙箱拒绝并报错退出码非 0——**只影响退出码，不影响产物**，看输出内容别只看状态。

## 通用铁律（四级都适用）

1. **指定介质，不要让模型自己选。** 「帮我讲讲 X」拿到的是默认文字。
2. **数值必标示意值 / 实测值。** 交互越好玩，越容易让人误以为看到的就是真模型。
3. **引用数字运行时回填**，不写死。
4. **一次只改一个约束。** 同时加三条，改好了也不知道是哪条起的作用。
5. **数量变量是内容密度的探针。** 填不出 8 个场景 → 内容撑不起视频，退回二级；填不出 3 张图 → 内容还不够结构化。
6. **越往上越难校对。** 视频的错误藏在一个你看得见、却听不见的地方（同步），而且修一次要从头渲染一遍。
7. 拿不准就用轻的：**写作最便宜，图表性价比最高。**
